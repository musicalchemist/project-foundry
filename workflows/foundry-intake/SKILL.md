# Select a project kit

Identify the mode: brainstorm, research, idea refinement, new build, existing-project support, or refactor. Ask only unanswered questions about audience/question, first useful result, exclusions, resources, data rights/sensitivity, consequences of error, and destination/agents.

Choose Explore, Build, or Operate maturity; add controls for sensitivity independently. Select experiment, research, app, ML, LLM, biology, or production profiles. For existing work, recommend only missing guidance. For refactors, name the contracts to preserve.

Return:

- A brief and feasibility decision: proceed, spike, narrow, blocked, or park.
- The cheapest experiment that could change that decision, with a cap and pass/fail criteria.
- The first useful result and dependency-ordered milestones with exit evidence.
- An adoption table: actual source path, destination, copy/reference/import mode, edits, dependencies, and activation condition.

If library files are inaccessible, label paths as proposals. Selecting a kit does not apply it to a repo.
