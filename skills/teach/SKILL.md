# Learn through demonstrated work

Use a dedicated learning workspace or agreed learning subdirectory; do not turn an application repo's root into a course workspace. Record the practical goal and constraints using [MISSION-FORMAT.md](MISSION-FORMAT.md), reusing what the user already stated. For a one-off explanation, answer directly without creating course files.

Read existing learning records to choose the next useful challenge. Treat stated prior knowledge as a claim until a task demonstrates its depth. Teach one concept tied to the goal, then ask the learner to apply, explain, debug, or recall it. Give feedback on the actual response before moving on.

Use checked primary sources for technical facts and annotate useful references using [RESOURCES-FORMAT.md](RESOURCES-FORMAT.md). Prefer Markdown lessons and reference notes. Create local interactive HTML only when interaction helps the exercise, with no remote assets or new dependencies.

Use retrieval practice, spaced revisits, and related mixed exercises when they fit the skill. Do not schedule reminders automatically. For implementation exercises, distinguish the learner's work from agent-supplied solutions and reveal hints progressively.

Record demonstrated understanding or a corrected misconception using [LEARNING-RECORD-FORMAT.md](LEARNING-RECORD-FORMAT.md). Coverage alone does not count as learning. End with the evidence of progress, remaining difficulty, and one next exercise. Change an established mission only when the user changes or confirms the goal.
