# Glossary format

Follow an existing project format. Otherwise use:

```md
# Ordering context

## Language

**Order**: A customer's request for specified products and quantities.
_Avoid_: Purchase, transaction, when referring to this request.

**Invoice**: A request for payment for an order.
```

Define project-specific concepts in one or two sentences. List alternative names only when they cause actual ambiguity. Group terms when distinct areas emerge. Exclude general programming terminology and implementation decisions.

For several contexts, a `GLOSSARY-MAP.md` can link each glossary and state relationships between contexts. Do not impose one canonical meaning across contexts that deliberately differ.

For scientific terminology, cite a definition or annotation/reference version when it affects interpretation. Label local operational definitions and unresolved ambiguity; a glossary is not evidence that a biological mechanism is true.
